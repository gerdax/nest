# Project studio and player

Run `python3 serve.py` and open `http://127.0.0.1:8937/editor.html`. The studio has two views: **Library** for shared card definitions and **Chapter** for the selected chapter's graph. The player at `/player.html` plays a selected chapter from the same browser's project, or an imported project/chapter file. No package installation is needed.

## Library and placements

Project JSON v2 (`kind: "nest-project"`) owns a Library, project variables and chapters. The Library contains four explicit card kinds:

- **Narrative**: description, artwork, optional visible heading and effects. Linear beats use narrative cards; Containers use one as their introduction.
- **Caption**: text presented without artwork, for short passages in Linear sequences.
- **Action**: name, description, artwork, requirements, costs, effects and Direct or Check resolution. Fork beats place actions.
- **Item**: name, description, artwork, collection effects and optional consumable use rules. Each Container item card grants one item. Repeated collection of the same definition does not stack.

Definitions hold shared content. Placements reference a definition with `definitionId` and have their own stable `id`. A placement can add conditions and effects. Connections belong to the chapter beat, never the shared card. **Edit shared** opens the definition and changes every use across chapters. **Used in** lists those uses and jumps to them. A used definition cannot be deleted.

**Create variant** copies the shared definition and rebinds just that placement. Checking **Use custom rules** on a shared Library Action copies the action's mechanics into placement overrides: requirements, costs, effects, Direct/Check mode, dice settings and outcome effects. The card's name, description and artwork remain shared. Unchecking **Use custom rules** discards custom rules and restores current source mechanics. Custom Actions edit their local source rules directly and do not show this checkbox; any saved placement rule overrides on Custom cards are discarded. Actions have one rule set: shared placements show a read-only source summary until **Use custom rules** is checked; Custom Actions edit their source rules directly. Existing additional Action requirements and effects are folded into that rule set on load. Unchecking the checkbox on a shared placement discards all customized rules. Inventory trigger and unavailable-card presentation remain separate placement settings. Other card types retain placement conditions and additional effects. Duplicating a beat copies its placements and connections while keeping the definition references shared.

**Card source** lists local templates such as **local [Vignette]**, **local [Caption]**, **local [Action]** and **local [Item]**, filtered to the types allowed in that beat slot, alongside shared Library cards. Selecting the same local type from a shared placement makes an editable copy. Selecting another local type preserves common content and artwork while using that type’s own gameplay rules; wiring follows its available outputs. Beat panels use Card source as their only type selector. Adding a card creates a local definition editable in the beat panel; new beats begin with local cards. **Add to library** promotes the same definition and links its current placement, so shared edits apply everywhere it is used. **Convert to local** explicitly creates an independent copy of the currently selected Library card. Local definitions are saved/exported with the project but do not appear in reusable-card dropdowns; inventory rules can still refer to local items. Duplicated beats receive independent local cards. Missing `visibility` means shared for older saves.

Artwork is stored as a path, not embedded in JSON. **Choose image file** matches the selected filename against project images under `assets/img` and fills the relative path. Duplicate filenames offer a path selection; unmatched files retain the previous path and require manual entry. Files are never uploaded or embedded. The local server generates the image catalog and static staging includes it. `./assets/img/...` uses supplied artwork. **Flip artwork horizontally** mirrors the image in previews, gameplay and inventory without altering the asset or text. **Show name on card** is off by default for every card kind. Enable it to display the name; Narrative cards can optionally use a custom heading. Descriptions and mechanical summaries remain visible. Internal names still identify definitions, beats and inventory entries. Retained v1 numbering flags remain inert.

## Chapter graph

Choose a chapter or add one. Linear beats place an ordered list of Vignette, Caption, Action or Item cards. Fork beats show Narrative or Action choices directly. Narrative choices have a single branch exit and apply effects only when selected; Action choices may add requirements, costs and checks. The source picker lists both kinds, and **Add narrative** creates a custom Narrative choice. Containers have a **Show introduction** toggle (enabled by default). Disabling it retains the introduction and its settings, skips its effects, and opens directly onto items. With the introduction enabled, Containers reveal Item cards with one upward swipe. Take selected items downward, or swipe upward to leave and discard all remaining items. Drag an output link onto a destination beat. Connection lines cannot be dragged; single-clicking a line does nothing, and double-clicking it disconnects that output. Dropping onto empty canvas unlinks that output; canceling, dropping outside the graph, or dropping onto an invalid beat preserves it. Clicking a card name opens that card’s panel without panning. Output descriptions ignore single clicks; double-clicking an output centers and selects its linked target beat. Card names also support keyboard activation. Unlinked outputs have a black dot. Connections can also be edited in the inspector; choose **Unlinked** to block departure or **End chapter** to finish intentionally. In saved data, `false` means Unlinked, `null` means End chapter, and a string identifies a target beat; existing `null` endings retain their behavior. Completion stops the deck and leaves restart controls outside it. There is no automatic next-chapter destination.

A new Random beat chooses one eligible, weighted destination on the canvas. Route conditions filter the candidates; the fallback handles no eligible route. Playback then follows the selected beat's own connections. Random does not regain control or count repeated encounters. Imported `legacyPool` beats keep the old weighted sequence-pool selection count and return behavior. Imported `legacySequence` beats preserve old internal fork topology; their inspector exposes the shared definitions rather than rewriting their behavior.

Direct actions have one connector. Check actions have **Success** and **Failure** connectors. Default settings are `1d20`, modifier `0`, target `10`. Configure the dice pool, fixed modifier and optional numeric variable modifier. Success means the sum of dice plus both modifiers is at least the target. Choosing an available action starts the existing 3D dice service in an overlay; the result is shown before routing. Requirements and affordability control availability. A completed attempt spends its costs on either outcome and applies common plus the corresponding outcome effects. Canceling or a dice/resolution error restores the action without spending costs or applying effects. See [run state](state-system.md).

## Inventory and playback

**Play chapter** and **Play selected** use a snapshot. Stop releases the session; Restart begins a fresh run. Up advances/chooses or leaves an open container; Down/Enter takes an item; Left/Right browse; Escape cancels a gesture or an active check. Canceled gestures change no state. Item ownership and collection effects commit only when the take departure completes. Leaving discards the remaining items without collection effects and preserves items already owned. Item cards in Linear sequences discard individually. The final item stages the next card using predicted post-collection state.

Inventory owns each Item definition at most once. Select a collected item to inspect it. A consumable's **Use** removes ownership and applies its use effects atomically when its conditions and routing pass. Using at a resource maximum still consumes ownership; bounds clamp the effect. Use is blocked during transitions, checks and after completion. Key/collectible items have no Use action. Inventory and variables reset on restart or reload; equipping and combat are deferred.

## Saving, migration and files

Changes autosave drafts to `nest.project.v2` in browser storage. If that key is absent, the studio can load `nest.chapter.v1` and migrate it without deleting the original save. Browser storage is specific to the browser and origin; it does not publish or write repository files. Undo/Redo covers document edits; canvas view state is separate.

**Export project** includes all chapters, definitions and variables. **Export chapter** creates a v2 `nest-chapter` package containing one chapter, project variable definitions and its referenced Library dependency closure. Both require a valid project. Importing a project replaces the working project; importing a chapter package or v1 chapter adds it with collision-safe remapping of chapter, definition, variable and inventory references. Invalid imports leave the current work in place.

V1 migration creates shared definitions and preserves gameplay identity using inventory aliases such as `<chapter-id>:<old-item-id>`. Migrated variables are prefixed with the chapter ID and their references are rewritten together. Old random sequence pools become `legacyPool`; complex forks become `legacySequence`. They are not silently converted to new Random routes. Validation rejects unresolved references, incompatible card kinds, invalid values/dice/quantities and graph cycles before playback/export; draft autosave permits incomplete references.

## Static staging and verification

Run `npm test` (or `beat --test tests/*.test.js`) for deterministic tests. Run `python3 build_pages.py /tmp/nest-pages` with a new or empty output directory outside the source assets. The staged site includes all three tools, project/studio modules, retained v1 chapter/editor dependencies, engine/UI modules, supplied usable artwork/fonts and licensed dice assets. `--include-editor` and `--include-dice` remain compatibility flags. Original playground files and layered PSD assets remain in the repository and are excluded from staging. Staging verifies local HTML, CSS and module references; it does not deploy or verify browser interaction, touch devices or real dice physics.

The interactive run preview opens in a floating window when you play a chapter or selected beat. Drag **Interaction preview** to reposition it, or use arrow keys while its move handle is focused. **Preview** reopens the window; closing it stops the current run. Card gestures remain independent of window dragging.

Set a PNG or other supported image back in **Project variables and chapter settings → Chapter card back**. Use the file picker for existing project artwork or enter a path such as `./assets/img/cardback.png`. The setting applies to the selected chapter; clearing it restores the generated back. Restart playback to use changes.

Card type tints are defined by `editorTint` alongside each type in `project/cards.js`. The editor uses that tint for whole placement panels, shared-definition panels, Library entries and type labels. New card types should define their own six-digit hex tint; the common editor styling applies automatically. These tints affect editor panels only.

The editor calls graph nodes **beats**; saved projects retain the `nodes` schema for compatibility. The panel heading shows the selected beat type (for example, **Linear** or **Fork**). Card sections start collapsed whenever a beat is selected, including reselecting the same beat. **Go to card** in the interaction preview expands, focuses and scrolls to the corresponding card section. Editing fields retains the current expansion state.

Local type switching retains name, description and artwork settings, including artwork hidden while Caption is selected. Each placement keeps temporary per-type rule drafts while editing the same beat. Returning from a Library source to a local type restores its local draft; Convert to local instead copies the selected Library source. Selecting another beat, changing chapters, reloading, importing or undoing/redoing discards inactive drafts. Only current card data is saved/exported. Clear, beside Add to library, resets the current local card and placement settings to defaults, removes its drafts, and preserves identity, ordering and story connections; Undo restores the cleared data.

Playback blocks any card departure that would traverse an Unlinked output, using disabled gesture feedback without spending costs, applying effects, rolling checks or changing inventory. Earlier cards in a Linear beat still advance normally. Fork checks require both outcome routes to be linked or set to End chapter. Introductions can still reveal choices/items. Final Item take/discard is also blocked when it would cross an Unlinked output. Eligible Random routes are checked without consuming a random draw.

Graph beats show their contained cards as rows tinted from the shared card-type palette. Horizontal dividers separate cards; a check Action shows its name once with Success and Failure outputs inside the same row. Enabled introductions are included. Linear and Container beats keep their shared Next output below their card rows. Action faces show their large description above the smaller rules summary in playback and editor previews.
