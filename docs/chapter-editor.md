# Project studio and player

Run `python3 serve.py` and open `http://127.0.0.1:8937/editor.html`. The studio has two views: **Library** for shared card definitions and **Chapter** for the selected chapter's graph. The player at `/player.html` plays a selected chapter from the same browser's project, or an imported project/chapter file. No package installation is needed.

## Library and placements

Graph card rows show rule letters beneath the card name: **T** for an Inventory trigger, **R** for requirements, **C** for costs and **E** for card effects (including Item collection effects). These reflect effective Library, local and custom placement rules. Dice success/failure effects do not add **E**, and the trigger's automatic ownership check does not add **R**. Hover the letters for their meanings.

Dice Actions now offer **Stat check** with Agility, Intelligence or Composure and
difficulty 1–10, alongside the existing **Custom check** controls. Global stats
start at 3 and stay out of the global player HUD. The exact one-decimal success
probability appears by or below the card; a smaller contextual panel below
shows the current stat value and formula. The underlying card back hosts the
dice and result after the Action leaves. See [Stats and card-based checks](stat-checks.md).

Select a beat on the graph and press **Delete** or **Backspace** (Mac Delete) to
remove it. The shortcut works while the graph is focused, ignores typing and
active drags, and uses the same undoable action as **Delete beat**. Click **Undo**
to restore the beat and its connections.

**Command+Z** undoes project edits and **Command+Shift+Z** redoes them (Ctrl on
Windows/Linux). Text fields retain their native text undo/redo; modal dialogs do
not trigger project history shortcuts.

Project JSON v3 (`kind: "nest-project"`; v1/v2 upgrade additively) owns a Library, project variables and chapters. The Library contains explicit card kinds and composite definitions:

- **Narrative**: description, artwork, optional visible heading and effects. Linear beats use narrative cards; Containers use one as their introduction.
- **Caption**: text presented without artwork, for short passages in Linear sequences.
- **Action**: name, description, artwork, requirements, costs, effects and Direct or Check resolution. Fork beats place actions.
- **Item**: name, description, artwork, collection effects and numeric **Permability**. Permability is a nonnegative integer: `0` (the default) means permanent; positive values limit accepted Action triggers. Each Container item card grants one item. Repeated collection of the same definition does not stack.

Definitions hold shared content. Placements reference a definition with `definitionId` and have their own stable `id`. Placements have their own appearance conditions and may customize their source rules. Connections belong to the chapter beat, never the shared card. **Edit shared** opens the definition and changes every use across chapters. **Used in** lists those uses and jumps to them. A used definition cannot be deleted.

**Create variant** copies the shared definition and rebinds just that placement. Checking **Use custom rules** on a shared Library Action copies the action's mechanics into placement overrides: requirements, costs, effects, Direct/Check mode, dice settings and outcome effects. The card's name, description and artwork remain shared. Unchecking **Use custom rules** discards custom rules and restores current source mechanics. Custom Actions edit their local source rules directly and do not show this checkbox; any saved placement rule overrides on Custom cards are discarded. Actions have one rule set: shared placements show a read-only source summary until **Use custom rules** is checked; Custom Actions edit their source rules directly. Existing additional Action requirements and effects are folded into that rule set on load. Unchecking the checkbox on a shared placement discards all customized rules. Inventory trigger and unavailable-card presentation remain separate placement settings. Shared Vignettes and Captions offer the same **Use custom rules** toggle for one **On progression effects** set. Local story cards edit that set directly. Existing additional progression effects are folded into the custom set for shared cards or the source for local cards; appearance conditions remain separate. Duplicating a beat copies its placements and connections while keeping the definition references shared.

**Card source** lists local templates such as **local [Vignette]**, **local [Caption]**, **local [Action]** and **local [Item]**, filtered to the types allowed in that beat slot, alongside shared Library cards. Selecting the same local type from a shared placement makes an editable copy. Selecting another local type preserves common content and artwork while using that type’s own gameplay rules; wiring follows its available outputs. Beat panels use Card source as their only type selector. Adding a card creates a local definition editable in the beat panel; new beats begin with local cards. **Add to library** promotes the same definition and links its current placement, so shared edits apply everywhere it is used. **Convert to local** explicitly creates an independent copy of the currently selected Library card. Local definitions carry `chapterId`, identifying the chapter that owns them. They are saved/exported with the project but do not appear in reusable-card dropdowns; inventory rules can still refer to local items in that chapter. Duplicated cards and beats receive independent local definitions and local dependency copies. Copies and cuts pasted into another chapter receive destination ownership and remapped definition, inventory and chapter-variable references. Missing `visibility` means shared for older saves.

Chapter card panels place **Copy** and **Paste** to the right of Add to library/Clear or Edit shared/Convert to local. Copy stores an internal snapshot that remains available while switching beats and chapters in this editor session; it is independent of beat and artwork clipboards. Paste replaces the target card and its placement rules in one undoable edit, preserving the target placement ID and applicable destination connections. Paste is disabled until a card of the same kind has been copied from this project. Local cards paste as independent destination-owned definitions with copied local dependencies and remapped chapter variables. Shared cards retain their Library source, together with detached placement custom rules; pasting never edits the shared definition. The clipboard clears on page reload.

Artwork is stored as a path, not embedded in JSON. **Choose image file** matches the selected filename against project images under `assets/img` and fills the relative path. Duplicate filenames offer a path selection; unmatched files retain the previous path and require manual entry. Files are never uploaded or embedded. The local server generates the image catalog and static staging includes it. `./assets/img/...` uses supplied artwork. **Flip artwork horizontally** mirrors the image in previews, gameplay and inventory without altering the asset or text. **Show name on card** is off by default for every card kind. Enable it to display the name; Narrative cards can optionally use a custom heading. Descriptions and mechanical summaries remain visible. Internal names still identify definitions, beats and inventory entries. Retained v1 numbering flags remain inert.

## Chapter graph

Hold **⌘** (Mac) or **Ctrl** (Windows/Linux) and drag a box on the graph to select multiple beats. Modifier-click a beat to add or remove it from the selection. The inspector shows **Multiple beats** and the selected count. Drag a selected beat’s header to move the group; one Undo restores the whole move. Escape cancels an in-progress selection or move. Select a single beat to resume card editing and single-beat commands.

Choose a chapter or add one. Linear beats place an ordered list of Vignette, Caption, Action or Item cards. Fork beats show Narrative or Action choices directly. Narrative choices have a single branch exit and apply effects only when selected; Action choices may add requirements, costs and checks. The source picker lists both kinds, and **Add narrative** creates a custom Narrative choice. Containers have a **Show introduction** toggle (enabled by default). Disabling it retains the introduction and its settings, skips its effects, and opens directly onto items. With the introduction enabled, Containers reveal Item cards with one upward swipe. Take selected items downward, or swipe upward to leave and discard all remaining items. Drag an output link onto a destination beat. Connection lines cannot be dragged; single-clicking a line does nothing, and double-clicking it disconnects that output. Dropping onto empty canvas unlinks that output; canceling, dropping outside the graph, or dropping onto an invalid beat preserves it. Clicking a card name opens that card’s panel without panning. Single-clicking an output label selects its linked target beat without panning; double-clicking centers it too. Keyboard activation also selects the target. Next outputs show only the arrow and target name. Card names also support keyboard activation. Unlinked outputs have a black dot. Connections can also be edited in the inspector; choose **Unlinked** to block departure or **End chapter** to finish intentionally. In saved data, `false` means Unlinked, `null` means End chapter, and a string identifies a target beat; existing `null` endings retain their behavior. Completion stops the deck and leaves restart controls outside it. There is no automatic next-chapter destination.

Fork and Linear beats offer **Unavailable actions** in Overrides. **Use project settings** is the default. Project settings and beat overrides offer **Hide unmet rules & triggers**, **Show unmet rules**, **Show unmet triggers**, and **Show unmet rules & triggers**. Rules include appearance conditions on every card type and Action requirements and affordability of costs; triggers require an owned, usable trigger item or matching item tag. A card is hidden if either unmet category is configured to hide, and otherwise stays visible but disabled until both are met. This includes Linear Vignettes, Captions, Items and resource cards, plus Container items using the project policy. Route checking stops at visible disabled cards instead of skipping them. Optional Fork and Container introductions retain their appearance-condition behavior. Already-owned item visibility keeps its separate setting. Random beats route to destinations, which use their own policy.

A new Random beat chooses one eligible, weighted destination on the canvas. Route conditions filter the candidates; the fallback handles no eligible route. Playback then follows the selected beat's own connections. Random does not regain control or count repeated encounters. Imported `legacyPool` beats keep the old weighted sequence-pool selection count and return behavior. Imported `legacySequence` beats preserve old internal fork topology; their inspector exposes the shared definitions rather than rewriting their behavior.

Under **Project settings**, **Allow beat cycles** applies to all chapters and is checked by default. When enabled, routes may revisit beats. Automatic routing-only cycles are blocked by the runtime with an **Automatic routing cycle** error; internal card cycles in legacy sequences remain validation errors.

Direct actions have one connector. Check actions have **Success** and **Failure** connectors. Custom checks default to `1d20`, modifier `0`, target `10`. Stat checks use `3d6 + selected stat ≥ 10 + difficulty`; their exact probability and contextual formula panel update from current run values. Configure custom dice pools, fixed modifiers and optional numeric variable modifiers in Custom check mode. Success means the sum of dice plus modifiers is at least the target. Choosing an available action starts the existing 3D dice service; the underlying card back shows the result before routing. Requirements and affordability control availability. A completed attempt spends its costs on either outcome and applies common plus the corresponding outcome effects. Escape cannot cancel a committed check; editor Stop/Restart or technical error aborts without spending costs or applying effects. See [run state](state-system.md).

## Inventory and playback

**Play chapter** and **Play selected** use a snapshot. Press **⌘Enter** (Mac) or **Ctrl+Enter** (Windows/Linux) in an editor field to commit the edit without starting playback. Press **Shift+Enter** from any editor context to restart the selected beat from its beginning. This uses the saved document without committing the focused field, changing cards or moving focus into playback. Stop releases the session; Restart begins a fresh run. Up advances/chooses or leaves an open container; Down/Enter takes an item; Left/Right browse; Escape cancels a gesture. A committed check cannot be canceled with Escape. Canceled gestures change no state. Item ownership and collection effects commit only when the take departure completes. Leaving discards the remaining items without collection effects and preserves items already owned. Item cards in Linear sequences discard individually. The final item stages the next card using predicted post-collection state.

Inventory owns each Item definition at most once. Select a collected item to inspect it and see its remaining Action triggers, or its permanent status. Set an Action placement's **Inventory trigger** to the item. All Action triggers share that owned item's count: each committed attempt consumes one, including both successful and failed checks. Blocked, canceled or interrupted attempts do not count. The item is removed after its final trigger. Inventory has no direct Use action; effects belong to the Action. After completion, **Next chapter** follows the explicit target in Chapter settings (None ends the game), carrying global variables and only shared Library Items (including remaining triggers). Unused local Items disappear; destination chapter variables reset, and explicit global overrides win. Restart restores the chapter's entry state; direct chapter selection, Play and reload start fresh. Equipping and 4d6 advantage are deferred. Combat/Death authoring is described in [combat](combat.md).

## Saving, migration and files

Changes autosave drafts to `nest.project.v3` in browser storage. If that key is absent, the studio can load `nest.project.v2` or `nest.chapter.v1` and migrate it without deleting the original save. Browser storage is specific to the browser and origin; it does not publish or write repository files. Undo/Redo covers document edits and reports browser save failures; canvas view state is separate. If a stored v3 save is malformed or structurally invalid, the studio preserves its exact raw text under `nest.project.v3.recovery` (with numbered suffixes for additional backups). **Download recovered save** downloads the exact original text, including malformed JSON, without changing the stored data. A failed or unverifiable backup blocks replacement of the damaged save. Save-failure warnings remain visible through other status messages until a successful save. The recovery warning remains visible through edits, other status messages and reloads until a project import is successfully saved. Import clears only the warning; recovery backups remain in browser storage.

**Export project** in the header includes all chapters, definitions and variables, including unfinished references and empty chapters. **Import project** accepts v2/v3 `nest-project` JSON and replaces the working project; unfinished drafts are allowed. In the chapter toolbar, **Export** creates a v3 `nest-chapter` package containing the selected chapter, project variable definitions, presentation settings and its referenced Library dependency closure. Only that package must pass playable validation; errors in other chapters or unused Library cards do not block export. **Import** beside it accepts v2/v3 `nest-chapter` JSON and adds the chapter with collision-safe remapping of chapter, definition, variable and inventory references. Both import actions are undoable; invalid or wrong-type files leave current work in place. The underlying model retains v1 migration for existing integrations.

Older v2 projects without local `chapterId` fields migrate on load/import. Reachable definitions acquire their chapter owner; definitions reused across chapters are copied with remapped local dependencies. Unplaced drafts infer ownership from chapter-variable rules, then fall back to the active or first chapter when no owner can be inferred. Historical local dependencies used by shared Library cards become shared to preserve their global identity. Explicit invalid owner IDs are reported rather than silently discarded. Full project exports retain owned drafts; standalone chapter exports retain only reachable dependencies.

V1 migration creates shared definitions and preserves gameplay identity using inventory aliases such as `<chapter-id>:<old-item-id>`. Migrated variables are prefixed with the chapter ID and their references are rewritten together. Old random sequence pools become `legacyPool`; complex forks become `legacySequence`. They are not silently converted to new Random routes. Validation rejects unresolved references, incompatible card kinds, invalid values/dice/quantities, disallowed chapter beat cycles and legacy internal card cycles before playback/chapter export. Automatic routing-only loops are caught by a runtime traversal guard and reported as **Automatic routing cycle**. Draft autosave and project draft files permit incomplete references.

## Static staging and verification

Run `npm test` (or `node --test tests/*.test.js`) for deterministic tests. Run `python3 build_pages.py /tmp/nest-pages` with a new or empty output directory outside the source assets. The staged site includes all three tools, project/studio modules, retained v1 chapter/editor dependencies, engine/UI modules, supplied usable artwork/fonts and licensed dice assets. `--include-editor` and `--include-dice` remain compatibility flags. Original playground files and layered PSD assets remain in the repository and are excluded from staging. Staging verifies local HTML, CSS and module references; it does not deploy or verify browser interaction, touch devices or real dice physics.

The interactive run preview opens in a floating window when you play a chapter or selected beat. Drag **Interaction preview** to reposition it, or use arrow keys while its move handle is focused. **Preview** reopens the window; closing it stops the current run. Card gestures remain independent of window dragging. Drag the bottom-right corner to resize width and height independently. The header reports the playfield viewport in CSS pixels; **Reset** restores the default size and proportions without restarting playback. The resize handle also accepts arrow keys (Shift for larger steps). Custom size survives minimizing and reopening within the current editor session, and stays within the desktop viewport. Card typography, labels, resource values/icons and padding scale together from the reset preview card design (273.6 CSS pixels wide), preserving text wrapping as the physical card changes size. The entire game composition uses the 359 × 745 reset viewport as its reference: proportional resizing scales the HUD, card, odds, USING mini, drawer and spacing uniformly. Only changes in aspect ratio redistribute spare space around the composition. The preview window header stays editor chrome.

Card backs use a separate background and transparent default PNG overlay in **Project settings → Card backs**. The defaults are `assets/img/ui/cardback.png` and `assets/img/ui/default.png`. The icon uses a full-card canvas; keep that canvas size when replacing it so the position stays consistent. Every card back keeps the default icon throughout interactions, including container opening, item collection/discard and dice checks. Original graphics and exported documents remain unchanged.

Project JSON and standalone chapter packages can define the shared appearance through `cardBack: { background, icons: { default }, iconScale }`. Omitted fields use defaults; `iconScale` defaults to `1`. Project settings allows changing the background and default icon paths for all chapters. Restart playback to use changes. Legacy contextual icon paths and switching settings are ignored.

Card type tints are defined by `editorTint` alongside each type in `project/cards.js`. The editor uses that tint for whole placement panels, shared-definition panels, Library entries and type labels. New card types should define their own six-digit hex tint; the common editor styling applies automatically. These tints affect editor panels only.

The editor calls graph nodes **beats**; saved projects retain the `nodes` schema for compatibility. The panel heading shows the selected beat type (for example, **Linear** or **Fork**). Card sections start collapsed whenever a beat is selected, including reselecting the same beat. **Go to card** in the interaction preview expands, focuses and scrolls to the corresponding card section. Editing fields retains the current expansion state.

Local type switching retains name, description and artwork settings, including artwork hidden while Caption is selected. Each placement keeps temporary per-type rule drafts while editing the same beat. Returning from a Library source to a local type restores its local draft; Convert to local instead copies the selected Library source. Selecting another beat, changing chapters, reloading, importing or undoing/redoing discards inactive drafts. Only current card data is saved/exported. Clear, beside Add to library, resets the current local card and placement settings to defaults, removes its drafts, and preserves identity, ordering and story connections; Undo restores the cleared data.

Playback blocks any card departure that would traverse an Unlinked output, using disabled gesture feedback without spending costs, applying effects, rolling checks or changing inventory. Earlier cards in a Linear beat still advance normally. Fork checks require both outcome routes to be linked or set to End chapter. Introductions can still reveal choices/items. Final Item take/discard is also blocked when it would cross an Unlinked output. Eligible Random routes are checked without consuming a random draw.

Graph beats show their contained cards as rows tinted from the shared card-type palette. Horizontal dividers separate cards; a check Action shows its name once with Success and Failure outputs inside the same row. Enabled introductions are included. Linear and Container beats keep their shared Next output below their card rows. Action faces show their name in the Big style above their authored description in the Medium style, matching item typography in playback and editor previews. Action names are always visible when provided; automatic rule summaries remain outside the card face.

Drag an **Unlinked** output onto empty canvas to open **Create and connect**, a bar of Linear, Fork, Container and Random beat icons. Choose an icon to create the beat at the drop point and connect it in one undo step. Arrow keys navigate the bar; Enter selects. Escape, an outside click or moving focus away dismisses it without changing the document. Connected outputs retain their existing blank-drop disconnect behavior.

Click **Project settings** in the header to open the project settings popup. This centered popup contains the project name, beat-cycle policy, text styles, project variable definitions and shared cardback artwork. At the bottom, **Start chapter** selects the game entry point and a full-width **Play from the start** button starts a fresh run there. It blocks the editor while the interaction preview remains usable above it. Close it with ×, Escape or a backdrop click. **Chapter settings** remains an expandable sidebar section for chapter name, the explicit **Next chapter** destination and chapter initial-value overrides. Chapter selectors sort alphabetically; their display order does not control progression. Settings edits save immediately and remain undoable after closing the popup.

New project and chapter variable IDs derive from their display names: lowercase ASCII letters, digits and underscores; spaces become underscores, Polish accents are transliterated and punctuation is removed. For example, **Los Ady poznany** becomes `los_ady_poznany`. Collisions receive `_2`, `_3`, etc.; empty names fall back to `variable`, and digit-leading IDs receive `variable_`. Editing a variable name also updates its ID and scoped requirements, effects, check modifiers, overrides and internal copy snapshots in one undoable edit. The built-in IDs `health`, `energy`, `agility`, `intelligence` and `composure` remain fixed. Loading/importing existing projects preserves legacy IDs until a name is edited.

The project-level `allowCycles` setting is authoritative; legacy chapter flags no longer override it. Files without a project setting default to allowing beat revisits. Chapter exports carry the project policy for standalone playback; importing a chapter retains the destination project’s policy. Automatic routing-only loops remain guarded.

Cardback background and icon artwork are project-wide. Unset fields use the default artwork. Chapter exports carry the shared design for standalone playback; chapter imports retain the destination project’s design.

**Delete chapter** is at the bottom of **Chapter settings**. A confirmation prompt names the chapter and explains what will be removed. Cancel leaves the chapter and interaction preview unchanged. Confirming deletion stops the interaction preview, selects the next remaining chapter (or the previous one when deleting the last entry), and can be undone in one step. The project must keep at least one chapter; the button is disabled for the only chapter. Shared Library cards and project variables are retained. The deleted chapter’s owned local definitions, including unplaced drafts, are removed together with its unused local dependencies. Unrelated drafts owned by other chapters are preserved; Undo restores the chapter and its removed definitions together.

Use **Copy**, **Cut** and **Paste** before **Duplicate** on the graph toolbar, or ⌘C/⌘X/⌘V, with ⌘D for Duplicate (Ctrl on Windows/Linux), to transfer the selected beat within the current project. The clipboard stays available when switching chapters in this editor session. Copy snapshots local cards as independent definitions while retaining shared Library references. Inventory definitions used by shared Library rules stay linked so those rules keep identifying the same items. Cut removes the original in one undoable step; its first paste preserves local card identities. Paste is a separate undoable step. Same-chapter copies keep valid outgoing routes; pasting into another chapter clears external routes and preserves self-links. Typing fields, selected text, dialogs and the interaction preview retain their normal clipboard shortcuts.

Drag a card name on the graph to reorder it or move it into a compatible beat. Hold Alt (Option on Mac) when dropping to copy instead. Introductions stay fixed. An insertion line marks the destination; incompatible beats show a red outline. Moving between Forks carries the card's outcome connections, except self-links when cycles are disabled. Other transfers clear incompatible outcomes, and copied outcomes start unlinked. Library cards remain shared; local copies are independent. Each drop is one undoable edit. Drag near a canvas edge to pan; Escape cancels.

Shared Item placements offer **Use custom rules** for **On collect effects** and **Permability**. The custom set replaces the source rules for that placement while preserving Item identity and appearance conditions. Unchecking it restores the current Library values; local Items edit their own rules directly.

**Remove from Library** always asks for confirmation, including for unused definitions. When a definition is placed in chapters, removal creates an independent local card for each placement, preserving content, effective custom rules, placement IDs and connections. Undo restores the definition and its shared links in one step. Removal stays disabled with an explanation when gameplay rules still reference the source, or when converting an Item would change its shared inventory identity or carry-over into another chapter. Update those uses first.

The Library inspector separates **Used in** (chapter placements) from **Referenced in** (cards whose rules depend on the selected card). Reference entries show the card name and the relevant node-style markers: **T** Inventory trigger, **R** Requirements, **C** Costs and **E** Effects. Multiple references from one card are grouped. Click a local card to reveal its exact chapter placement, or a shared card to open its Library source; marker tooltips explain the letters.


## Graph selection and panning

Drag empty canvas normally to pan; the current selection is retained during a pan. A single click on empty canvas deselects all beats, leaving the inspector empty until another beat is selected. Deselecting is view state and does not save or create an undo entry.

To select several beats, hold Cmd (Ctrl on Windows/Linux) and drag a rectangle, or double-click empty canvas and keep the second press held while dragging. Beats intersecting the rectangle are selected. Drag a selected beat's header to move the selected group together in one undoable edit. Escape, pointer cancellation or lost capture cancels the gesture. The second-press shortcut requires two nearby clicks within 450 ms; a preceding pan, node/connector interaction or zoom does not arm it. Cmd/Ctrl-click still toggles individual beats. Touch dragging retains ordinary panning.


Graph gesture verification (25 October 2026): all 2,256 deterministic tests pass, including 88 graph-event tests. The isolated `tests/fixtures/graph-selection.html` was exercised with native in-app browser pointer gestures: click then held-second-press drag selected A/B without panning or editing; header drag moved both in one edit; ordinary drag preserved selection while panning; blank click cleared selection without adding an edit. The actual studio also retained empty selection across Library/Chapter switches with beat-specific tools disabled. The fixture reported no console warnings/errors. Static staging and `git diff --check` pass. Physical touch and platform-specific double-click-speed settings were not verified.

With multiple beats selected, Delete, Backspace or Cmd+Backspace removes the group in one undoable edit. Incoming connections to removed beats become unlinked. If the start beat is removed, the first remaining beat becomes the start.

Copy, Cut, Paste and Duplicate also work on the selected group, using the toolbar or the usual Cmd/Ctrl+C/X/V/D shortcuts. Groups retain their relative layout; pasted and duplicated beats stay selected together. Internal links connect the new copies. Links outside the group stay connected when pasting within the same chapter and become unlinked across chapters. Referenced local cards and chapter variables are remapped together, while shared Library cards remain shared. Each cut, paste or duplicate is one undoable edit. Cutting unlinks incoming connections; Undo restores them.

Alt-drag a selected beat’s header to duplicate the selected group at the drop position. Ghosts preview all copies; originals stay in place. Internal group links connect the copies, while exits outside the group are unlinked, matching single-beat Alt-drag behavior. The copies stay selected and the duplication is one undo step. Escape or pointer cancellation discards the preview.

Shift+Space closes the interaction preview and stops its playback. Plain Space continues to minimize or restore it. Text fields retain their normal space input.

### Combat Library additions

Weapon is an Item subtype providing Library Combat Actions. Combat Action and Effect Card are separate types; Enemy is a self-contained composite with embedded attacks and presentation cards. Combat beats select an Enemy without overrides and connect Victory to a following beat. Each chapter also has one mandatory portless Death beat, initially an empty local Caption. See [combat authoring](combat.md) for controls and supported first-milestone mechanics.


Costs use an Energy/Health resource selector in both Library and chapter card
panels. New costs default to Energy and show their badge. Each cost has **Hide
badge** below Amount, alongside Remove; checking it hides only that entry's
contribution to the top-right resource badge. Requirements and payment are
unchanged. Existing item/other-variable costs remain intact as disabled legacy
selections until explicitly retargeted or removed.

Action Progression effects apply on completion, on either dice outcome. Use the
separate **On success effects** and **On failure effects** lists on ordinary and
Combat Actions for outcome-specific changes. These sections appear for dice checks
after Check settings and before the card preview. Direct actions hide and ignore
the lists without deleting their saved contents.
